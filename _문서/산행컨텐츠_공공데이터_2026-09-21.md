## 2. data.go.kr 함정 (korea-mountain 실측, 코드에 반영)

- 인증키는 **Encoding 키**를 그대로 붙인다. 다시 인코딩하면 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`.
- API 마다 `serviceKey`/`ServiceKey`, `_type`/`type`, 성공코드 `00`/`0` 이 다르다. 산정보는 XML 전용.
- 실패해도 HTTP 200 이고 오류는 XML 로 온다. 결과 1건이면 `items.item` 이 배열이 아니다.
- 산악기상은 `tm`(정시) 없이 부르면 값이 전부 `-`. 정시 직후엔 일부 지점만 올라와 최대 4시간 거슬러 찾는다.
- 산 이름은 유일하지 않다. 산정보는 목록을 돌려주고, 봉우리 GPX 는 시도로 고른다.
- 봉우리 폴더 코드 앞 2자리는 법정동코드가 아니다. 유명 산 위치로 맞춘 표(11 서울 · 12 인천 · 13 경기 · 23 강원 · 32 대구 · 33 경북 · 43 충북 · 52 부산 · 53 경남 · 63 전북 · 72 광주 · 73 전남 · 82 대전 · 83 충남). 울산·세종·제주는 자료에 없다.

## 3. 글에서의 규칙

- 거리·고도는 GPX 실측 → 그대로. 소요시간은 네이스미스 추정(4km/h + 600m/h, 휴식 제외) → "약" 또는 본인 실측.
- GPX 시설명은 원문 그대로 소제목 고유명사로. 유무·운영은 발행 전 확인(`[확인 필요]`).
- 개인 GPS 기록 기반이라 공식 등산로가 아닌 길이 섞일 수 있고 통제·폐쇄가 반영돼 있지 않다. 국립공원은 knps.or.kr 통제 현황.
- 걷지 않은 코스는 쓰지 않는다. 자료는 걸은 코스의 숫자를 정확히 하는 데 쓴다.

## 7. 산림청 / 블랙야크 목록 구분 (같은 날 추가)

- "100대명산" = 산림청 선정 100대 명산. 블랙야크 명산100(BAC) 은 별도.
- BAC 목록은 공개 API 가 없다. 사이트가 명산100 페이지를 그릴 때 쓰는 내부 주소(`bac.blackyak.com/BAC/ChallengeProgram/getlist.asp?program_id=114`, 자바스크립트 배열 텍스트)를
  GitHub `daehyub71/blackyak-100` 의 크롤러와 같은 방식으로 받아 `bac100.json` 에 둔다. 주소·형식이 바뀌면 깨지므로 자동 갱신하지 않고 버튼/`--bac` 로 받는다.
- 매칭: 이름(괄호 제외) 같은 산 중 좌표 25km 안 가장 가까운 것 → 없으면 시도 같은 것. 실측 99개 중 98개 매칭, 산림청과 겹치는 산 76개.
  코스 자료에 없는 BAC 산 7곳(내변산·불갑산·오대산 노인봉·비로봉·용봉산·지리산 바래봉·반야봉)은 코스 없는 행으로 산 찾기에만 나온다.
- 산 찾기 "목록" 필터(전체/산림청/블랙야크/둘 다/봉우리만)와 "BAC 인증 지점" 열, 3-1 기획 메모 첫 줄 "목록:" 에 반영.
- 3-1 화면: [🔎 어디 가지? 조건으로 산 찾기] 를 첫 번째 큰 버튼으로, 오른쪽 버튼들은 둘째 줄로 옮겨 잘림을 없앴다.
- 사진 URL 은 블랙야크 서버 것이라 쓰지 않는다. 이름·인증 지점·좌표·주소만 쓴다.

## 8. GPX 거리 계산 교정 · 들머리별 경로 (2026-09-21 오후)

**버그:** 파일 하나를 트랙 하나로 보고 모든 점을 이어 거리·상승을 쟀다. 그런데 이 자료는 한 산의 **등산로 망을 여러 `<trk>` 로** 담는다
(100대명산 607개 중 38%, 봉우리 6,748개 중 47%, 최대 382구간). 구간 사이는 순간이동이라 그 거리와 고도 점프가 전부 더해졌다.
사용자가 "수암봉은 2.2km인데 21km로 나온다" 고 짚어 발견했다. 수암봉 실제: 18구간 · 망 총 11.7km · 정상까지 2.3km.

**교정:** 구간 경계를 지키고, 구간 끝점을 50m 이내로 묶어 그래프를 만든 뒤 다익스트라로 **들머리마다 정상까지 최단 경로**를 낸다.
코스 대표값은 가장 낮은 들머리 기준. `routes` 에 들머리별 선택지를 최대 8개 싣는다(들머리가 200m 안이면 같은 길로 본다).

| 예 | 전 | 후 |
|---|---|---|
| 수암봉 | 21.0km / 1,899m | 2.3km / 346m (52→393m), 들머리 6갈래 |
| 수락산 | 42.7km / 4,560m | 3.7km / 636m |
| 연인산 | 28.8km / 1,902m | 4.9km / 840m |

**남은 것:** 경로 미확정 81개(1.1%, ⚠ 표시) · 20km 초과 6개(실제 종주) · 중턱부터 찍힌 트랙 803개(11%, ⚠ 표시).
산 찾기의 대표 코스는 (1) 중턱 기록 아님 (2) 그 산 최고점의 80% 이상 도달 을 만족하는 것 중 최단으로 고른다.

## 9. 들머리 이름·정렬·목록 체크박스 (2026-09-21 저녁)

- **들머리 이름**: `label_routes()` 가 들머리 좌표 400m 안의 지점 이름을 붙인다. 유형 우선순위 ENTRY > PARK > TRANS > INFO > …,
  GPX 웨이포인트(색인 시) → 숲길·관광 POI API(조회 시) 순. 못 찾으면 `bearing_ko()` 로 "정상 남서 3.0km".
  봉우리 자료는 웨이포인트가 없어 정상 좌표를 트랙 최고점에서 가져온다(`summit_lat/lon`).
- **정렬**: 3-1 코스 표는 들머리 고도 오름차순(같으면 거리순). 중턱부터 찍힌 기록은 자연히 아래로 가고 회색으로 표시된다.
- **목록 체크박스**: 산 찾기의 `목록` 콤보를 없애고 체크박스 3개로 바꿨다 — `100대명산(산림청)` · `100대명산(블랙야크)` · `목록 밖 봉우리`.
  둘 다 체크 = 두 목록에 모두 든 산(경기 9곳). `LISTS` 이름도 바꿨고 옛 이름(`산림청 100대명산` 등)은 `LIST_ALIAS` 로 계속 받는다.
- **생성기 원본 복구**: `content_trend_radar_v18.py` 는 `_base/content_trend_radar_v17.py` + `_base/make_v18.py` 로 만든다.
  작업 중 `OLD/` 가 사라져 생성이 조용히 실패했고 두 차례 변경이 빌드에 빠졌다. 이제 `_base/` 에 원본과 생성기를 함께 둔다.
  **v18 을 직접 고치지 말고 `_base/make_v18.py` 를 고친 뒤 실행한다.**

## 10. 정상 도달 판정 · 도착 봉우리 · 표 정렬 (2026-09-21 밤)

사용자가 "감악산인데 최고점이 364m·322m 로 제각각이다, 최종 목적지를 어떻게 구분하나" 라고 짚어 발견.
GPX 최고 고도는 트랙이 오른 높이지 산 정상이 아니었고, 열 이름을 `정상 m` 이라고 붙여 오해를 키웠다.

- `mountain_summit_m()`: 산림청 산정보 → 블랙야크 고도 → 코스 최고점 순으로 그 산의 정상 높이를 정한다.
- `mark_summit_reach()`: 정상보다 60m 이상 낮은 코스는 `reaches=False` → `⚠ 정상(Nm)까지 안 간다`.
- `label_top()`: 최고점 250m 안의 PEAK·VIEW·SCENERY 웨이포인트를 도착 봉우리 이름으로. 갈림길·쉼터는 제외.
- 열 이름 `정상 m` → `최고점 m`, 새 열 `도착 지점`. 정상 미도달·중턱 기록은 회색.
- 실측 감악산: 코스 9개 중 정상 도달 6 / 중간 봉우리 3 (364m·322m·606m 악귀봉).
- 모든 목록표를 가운데 정렬로 통일했다(열 경계에서 글자가 붙어 보이던 문제). 오른쪽 기획 메모·글 방향 패널은 텍스트라 왼쪽 정렬 유지.
