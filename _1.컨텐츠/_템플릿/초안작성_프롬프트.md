# 네이버 블로그 초안 작성 지침

> **용도:** 이 문서 전체를 Claude 채팅의 프로젝트 지침(또는 대화 첫 메시지)에 붙여넣는다.
> 그러면 Claude Code가 그대로 읽어서 네이버에 자동 발행할 수 있는 md 파일이 나온다.
> **이 형식을 벗어나면 자동 발행이 실패한다.**
>
> 📚 **글의 내용 규칙은 `Blog\지침\` 폴더의 지침을 따른다** — `지침\블로그_마스터지침.md`(공통) + 분야 지침(등산·먹자·축제·축구·클립). 이 문서는 파일 형식만 다룬다. 마스터와 겹치는 형식 규칙(마스터 2장)을 고치면 이 문서도 같이 고친다.

---

## 1. 출력 파일 구조

md 파일은 반드시 아래 3개 구역 순서로 쓴다.

```
[구역 A] 메타 정보     ← 경계선 위
===== ✂️ 여기부터 복사 =====
[구역 B] 본문          ← 네이버에 들어갈 내용만
===== ✂️ 여기까지 =====
[구역 C] 작업 메모     ← 경계선 아래, 발행 시 자동 제외
```

경계선 두 줄은 **글자 하나도 바꾸지 않는다.** 띄어쓰기·이모지 포함 정확히 그대로.

---

## 2. 마커 (필수)

### 2-1. 제목 · 카테고리 — 구역 A

```
[[TITLE: 인왕산 등산코스 소요시간 | 산은 공짜인데 뒤풀이가 17만 5천원]]
[[CATEGORY: Hiking > 서울]]
```

- 각각 **한 줄**로 쓴다. 줄바꿈 금지.
- 제목 안에 `|`를 써도 된다 (구분자로 쓰지 않음).
- **제목을 정하기 전에 검색어 점검표(마스터 10-8)를 돌린다** — `cd "C:\Users\user\Desktop\자동화\블로그용\Keyword_Reader" && python title_check.py --q "씨앗 검색어" --md`. 나온 표와 판정을 **초안 작업 메모에 반드시 붙이고**(인수인계서가 있으면 1절에도), 앞 검색어·소주제 명사는 그 표에서 고른다(큰 말은 좁히기 · 의도 하나 · 경쟁 높은 말은 하나씩 · 핵심 검색어는 제목에 한 번만). **홈판형(10-7)도 앞 검색어 확인용으로 돌린다**(2026-10-12 — 「정효볼」 10 vs 「이정효감독」 4,940 사례). 표가 없으면 `draft_lint.py`가 막는다.
- **제목은 감으로 먼저 짓지 않는다.** 순서: 점검표(10-8) → 내 손의 숫자·장면(10-6 ②) → 없으면 발견형, 있을 때만 질문형(10-5) → 답은 첫 문단(10-6 ④). 네 단계를 아래 「🧭 지침 경유표」에 적는다. 제목을 사용자에게 보이기 전에 16-3(실제 블로그 탭 상위 글 보기)과 제목 숫자 대조(본문 표 값·반올림)까지 끝낸다(2026.10.12).
- 이 두 줄은 반드시 경계선 **위**에 둔다.

### 2-2. 이미지 — 구역 B

```
[[IMG:20260905_163738.jpg | 인왕산 정상 338.2m 정상석]]
```

- `파일명 | 캡션` 순서. 파이프(`|`) 앞뒤 공백은 있어도 없어도 된다.
- **파일명은 사용자가 준 목록에서 그대로 복사한다. 절대 지어내지 않는다.**
  확장자·언더바·괄호까지 정확히. (`20260905_163823(0).jpg` 같은 것도 그대로)
- 본문에 **등장하는 순서 = 네이버에 삽입되는 순서**다. 번호를 붙이지 않는다.
- 마커는 **단독 줄**에 둔다. 문장 중간에 넣지 않는다.
- 캡션은 사진 설명. 비우려면 `[[IMG:파일명 | ]]`.

### 2-3. 표 — 구역 B

평범한 마크다운 표를 그대로 쓴다. 별도 마커 없음.

```
| 항목 | 값 |
|---|---|
| 정상 | 338.2m |
```

- 자동화가 네이버 표 도구로 변환한다.
- **3열을 넘기지 않는다.** 모바일에서 잘린다.
- 표 안에 이미지 마커를 넣지 않는다.

### 2-4. 볼드 — 구역 B

굵게 할 문장을 본문에 **직접** 표시한다.

```
**여기가 등산 전 마지막 화장실이다.**
```

- 자동화가 `**` 기호를 떼고 실제 굵게 서식을 적용한다.
- **섹션당 1~2개**만. 남발하면 강조 효과가 죽는다.
- 별도로 "볼드 지정" 목록을 만들지 않는다. 본문 표시만으로 충분하다.

## 3. 본문(구역 B) 작성 규칙

### 구조

```
도입부 (2~4문장, 결론이나 숫자를 먼저 던진다)

---

⛰️ 이모지 + 소제목 (평서문, 결론을 담는다)

내용 2~5문장

[[IMG:파일명 | 캡션]]

---

🚶 다음 소제목
...

#태그1 #태그2 #태그3
```

### 소제목
- **이모지 하나 + 공백 + 문장** 형태. `#`, `##` 마크다운 헤딩 금지.
- 명사형이 아니라 **평서문으로 결론을 담는다.**
  - ✅ `🚻 화장실은 인왕배드민턴장 옆이 마지막이다`
  - ❌ `🚻 화장실 위치`
- 소제목만 쭉 읽어도 글의 답이 나와야 한다.

### 구분선
- 섹션 사이는 `---` 한 줄. (네이버에서 구분선으로 변환됨)

### 문체
- 반말체로 통일. (`~야`, `~어`, `~다` 혼용 가능하나 존댓말 금지)
- 검색 키워드(예: `인왕산 등산코스`)를 도입부와 소제목에 자연스럽게 넣는다.

### 태그
- 본문 **맨 끝** 한 줄에 `#태그` 나열. 8~10개.
- 경계선 **안쪽**에 둔다.

---

## 4. 금지 사항

| 금지 | 이유 |
|---|---|
| `#`, `##` 마크다운 헤딩 | 네이버에서 글자로 찍힘 (`#태그`는 예외) |
| `- `, `* ` 마크다운 목록 | 기호가 그대로 노출됨. 줄바꿈으로 나열할 것 |
| ``` 코드블록 | 네이버에 대응 서식 없음 |
| 링크 `[텍스트](url)` | 자동화 미지원. 링크는 발행 후 직접 추가 |
| 목록에 없는 파일명 | 발행 시 "파일 없음" 오류 |
| 미발행 글 링크 | 깨진 링크가 됨 |
| 확인 안 된 사실·수치 | 지어내지 말고 구역 C의 「남은 확인 사항」에 적는다 |

## 5. 작업 메모 (구역 C)

경계선 아래. 발행 시 자동으로 잘려나가므로 무엇을 써도 안전하다.

```
# 🚧 작업 메모 — 발행 전 이 아래는 전부 삭제

## 🧭 지침 경유표 (마스터 2-11 — 비우면 자동 입력이 막힌다)

| 항목 | 기록 |
|---|---|
| 분야 지침 | 어느 지침의 몇 장을 봤나 (없으면 「마스터만」) |
| 유입 꼴 (10-7) | 검색형 / 홈판형 + 이유 |
| 10-8 점검표 | 날짜 · 씨앗 · 고른 앞 검색어(검색량·경쟁) — 표 전체는 아래에 붙인다 |
| 10-6 ① 앞 검색어 | 고른 말 (+ 소주제 명사는 본문 소제목에 있는가) |
| 10-6 ② 내 숫자·장면 | 내가 재거나 본 것 하나 (남의 말 아님) |
| 10-6 ③ 꼴 | 발견형 / 질문형(10-5: 누를 사람 · 이미 믿는 것) / 다섯 공식 중 몇 번 |
| 10-6 ④ 첫 문단의 답 | 제목이 약속한 답이 첫 문단 어디에 있나 |
| 16-3 검색 화면 | 날짜 · 앞 검색어로 실제 블로그 탭 상위 글 제목을 본 결과 · 내 글의 차별점 한 줄 |
| 제목 숫자 대조 | 제목의 숫자마다 본문 표의 원래 값과 반올림 (예: 32% ← +31.5%) — 숫자 없는 제목이면 「제목에 숫자 없음」 |
| 사실·숫자·영상 (0-1·0-4·0-11) | 직접 계산 숫자 여부 · 영상 인용은 자막+whisper 두 판독 |
| 썸네일 (5-4·분야 예외) | ①요약+궁금증 ○/△/✕ ②제목 연상 ○/△/✕ ③본문에 있음 ○/✕ — 무엇을, 왜 (예: `①○ ②○ ③○ — 정상석 사진, 제목 앞 검색어 수암봉, 본문 2절 정상 사진`) |
| 말투 (2-7-1) | 끝맺음 「~어/~야」 몇 % · 3연속 몇 곳 · 질문 몇 번 · 짧은 문장 몇 % (draft_lint 숫자 그대로) + 바꾼 곳 한 줄 |
| 발행 전 검증 (9장·15장) | 전체 글 목록에 같은 글 없음 · 하루 발행 수 |

> 한 칸이라도 비거나 「…」「□」「TODO」면 `python _1.컨텐츠\_자동화\draft_lint.py <초안.md>` 가 ❌ 를 내고, `fill_editor.py` 는 새 글을 넣지 않는다.

```
| 말 | 월 검색량 | 경쟁 | 블로그 문서 | 상위 30 중 90일 | 지수 | 출처 |   ← title_check.py --md 표를 그대로
```

## 📷 썸네일 추천
파일명 + 이유 — 마스터 5-4 세 질문(① 글 전체를 말하며 궁금증 ② 그림만 봐도 제목 연상 ③ 그 장면이 본문에 있음)에 각각 답한다

## 🚫 이번 초안에서 뺀 것
- 항목 — 뺀 이유

## ⏳ 남은 확인 사항
- 확인 필요한 것

## ✅ 발행 전 체크
- [ ] 본문에 마크다운 기호 남아 있지 않은가
- [ ] 사진 순서가 시간 흐름과 맞는가
- [ ] 표가 3열 이하인가
- [ ] 얼굴·차량번호판 마스킹 필요한 사진 표시했는가
- [ ] 하루 발행 3편 기본, 필요하면 최대 5편 — 클립 등록 포함 (같은 날 같은 장르 겹치지 않게, 마스터 15장)
- [ ] `python _1.컨텐츠\_자동화\draft_lint.py <초안.md>` ✅ 통과 (마스터 2-11 — 실패하면 자동 입력이 막힌다)
```

## 6. 사용자가 줘야 할 입력

### 사진 파일명 목록 (필수)

Claude Code에서 아래를 실행하면 목록이 클립보드에 복사된다.

```bash
ls "폴더경로/사진폴더" | clip
```

이걸 채팅에 붙여넣으면 된다.
**파일명에 촬영 시각이 들어 있으면(`20260905_163738`) 그 시간 순서를 글의 시간 흐름에 맞춰 배치한다.**
어느 사진인지 확신이 없으면 지어내지 말고, 구역 C에 「사진 확인 필요: N번」이라고 적는다.

### 그 외
- 다녀온 내용 / 대화 / 메모
- 목표 검색 키워드
- 카테고리

## 8. 파일 저장 위치

```
C:\Users\user\Desktop\Blog\네이버 블로그\<YYMMDD>_<주제>\
├── <주제>_post_draft.md   ← 이 지침대로 작성된 초안
└── <사진폴더>\             ← 원본 사진
```

md 파일과 사진 폴더는 **같은 폴더 안**에 둔다. 자동화가 상대 경로로 찾는다.
