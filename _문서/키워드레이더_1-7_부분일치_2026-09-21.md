# 1-7 글 방향 자료 — AI 분석이 막히던 원인과 수정 (2026-09-21)

## 증상

1-1 에서 K리그 219건을 모은 뒤 1-7 에서 `k리그2 순위` 로 **판단 자료 모으기** → **AI 로 글 방향 분석** 을 누르면
"먼저 판단 자료를 모으거나 최근 자료를 여세요" 가 떴다. 자료는 분명히 모았는데도 그랬다.

## 원인 — 검색어의 낱말이 전부 들어간 기사만 통과시켰다

`collect_dossier` 의 필터가 이랬다.

```python
patterns=[candidate_pattern(t) for t in keyword.split()]
if all(p.search(text) for p in patterns): articles.append(a)
```

실측(2026-09-21, 최근 7일):

| 단계 | 건수 |
|---|---|
| 구글 뉴스 응답 | 53 |
| 기사형 · 기간 내 | 49 |
| `k리그2` 포함 | 13 |
| `순위` 포함 | 6 |
| **둘 다 포함** | **0** |

기사는 "순위" 라고 쓰지 않는다. "2위 도약", "선두 굳히기", "승격 판도" 라고 쓴다.
검색어는 사람이 검색창에 치는 말이고 기사 제목은 기자가 쓰는 말이라 겹치지 않는다.
그래서 기사 0건 → `start_ai` 의 `not self.dossier['articles']` 가드에 걸린 것이다. 안내문이 원인을 가렸다.

## 수정

**1. 전부 일치가 3건 미만이면 주어만 맞은 기사도 받는다.** 부분 일치로 표시한다.

```
관련 기사 13건 (낱말 전부 일치 0건 + 핵심어 「k리그2」 만 맞은 부분 일치 13건) / 표시 매체 5개
※ 검색어의 낱말이 전부 들어간 기사가 적어 범위를 넓혔습니다.
[E4] [부분: k리그2 만 일치] K리그2 수원FC, 전남 잡고 2위 도약 가능할까
```

전부 일치가 3건 이상이거나 낱말이 하나면 예전과 같다. `k리그1` 은 62건 전부 일치라 넓히지 않는다.

**2. 핵심어는 '주어' 로 고른다.** 한국어 검색어는 앞이 대상, 뒤가 의도어다.
`INTENT_WORDS`(순위·추천·가격·방법·후기·비교 …)를 제외하고 남은 첫 낱말을 쓴다.

시행착오를 남겨 둔다. 처음엔 **가장 긴 낱말**로 골랐다가 `제주 항공권` 에서 `항공권` 이 뽑혀 중국 노선 기사가 들어왔다.
다음엔 **가장 드문 낱말**로 바꿨더니 `k리그2 순위` 에서 `순위` 가 뽑혀 K3·경남 기사가 섞였다.
수집된 기사 자체가 이미 질의로 편향돼 있어 그 안의 빈도는 변별력이 없다.

| 검색어 | 핵심어 | 결과 |
|---|---|---|
| `k리그2 순위` | k리그2 | 13건, 전부 K리그2 기사 |
| `제주 항공권` | 제주 | 3건, 제주 노선 기사 |
| `k리그1` | k리그1 | 62건, 넓히지 않음 |

**3. 안내문을 원인에 맞게 고쳤다.** 자료를 모았는데 기사가 0건이면 그렇게 말하고, 검색어를 줄이라고 안내한다.

## 덤 — sqlite 연결 누수

자체검사 41개 중 10개가 계속 빨갰다. `sqlite3` 의 `with` 는 **트랜잭션만 끝내고 연결은 닫지 않는다.**
`Store.connect()` 가 호출될 때마다 핸들이 쌓였고, 윈도우에서 임시폴더 정리가 막혔다.
`with` 를 벗어날 때 커밋/롤백 후 `close()` 하는 래퍼를 넣었다.

**43개 전부 통과한다.** GUI 를 오래 켜 두면 핸들이 계속 쌓이던 문제도 같이 사라진다.
