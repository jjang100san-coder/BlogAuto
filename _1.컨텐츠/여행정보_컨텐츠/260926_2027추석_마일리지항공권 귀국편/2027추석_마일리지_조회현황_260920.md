## 1. 핵심 결론 4줄

1. **귀국편까지 전부 열렸다.** 오픈 한계일은 **2027-09-21**(조회일 + 360일). 추석 왕복을 이제 통째로 짤 수 있다.
2. **완전한 왕복이 되는 건 라스베이거스뿐이다.** 가는 편·오는 편 모든 날짜가 9석이다.
3. **파리는 귀국이 막혔다.** 9/17~9/21 전 편 매진. 가는 편은 열려 있는데 돌아올 방법이 없다.
4. **좌석은 움직인다.** 엿새 사이 매진이 좌석으로 돌아온 게 3건, 줄거나 사라진 게 4건이다. → 6장

### 오픈 시각 — 오전 9시 정각 (2026-09-27 실측, 확정)

2027-09-22 가 열리는 순간을 1분 간격으로 폴링해 잡았다(대조군 ICN-NRT).

```
08:59:34   0편
09:00:42   ★ 열렸다 — 5편
```

공지의 "오전 9시"가 맞다. **더는 "몇 시인지 모른다"고 쓰지 말 것.**

**롤오버는 두 단계다.** `ERT.10032`(한계일 밖) → **오류 없이 0편**(당일 9시 전) → `N편`(열림).
2단계는 전날 오후~당일 09:00 사이에 관측된다. 한 덩어리로 보면 오판한다.
폴러: `scratchpad/poll.mjs`.

추석 주간은 **9/21까지 전부 열렸다.** 오픈 예정일 표는 더 이상 필요 없어 삭제했다.
그 뒤 날짜가 필요하면 `조회일 + 360일`로 계산하면 된다.

🚫 앞으로 "오픈 직후라 재고가 덜 실렸다"를 설명으로 쓰지 말 것.

### 6-4. 그래서 어떻게 읽어야 하나

- **한 번 보고 포기하지 않는다.** 매진이어도 취소분이 돌아온다.
- **오픈 당일 값은 믿지 않는다.** 최소 며칠 뒤 다시 찍는다.
- 🚫 **다시 열린 좌석을 "취소분"이라고 부르지 말 것.** (2026-09-27 사용자가 잡아낸 오류)
  화면에 보이는 건 `0석 → 며칠 뒤 N석` 뿐이고, **누가 취소한 자리인지 항공사가 그때 더 푼 것인지 구분할 방법이 없다.**
  오히려 `0석 → 9석 이상`처럼 한 번에 뛴 건 낱개 취소로 보기 어렵다(1석·3석 복귀와 모양이 다르다).
  **"다시 열렸다"까지만 쓴다.**

### 6-5. 프레스티지 집계

**4개 노선 × 양방향 × 09-10~09-21 전 날짜 매진.**
9/20에 유일하게 있던 PRG→ICN 09-13의 1석마저 나갔다. **현재 확보 가능한 프레스티지는 0석이다.**

## 8. 재조회 방법

```
프로젝트: C:\Users\user\Desktop\Blog\projects\mileage-seat-search
```

1. 크롬에서 koreanair.com 로그인
2. 브리지 기동 → Playwright 확장에서 해당 탭 `Allow & select`
3. 인페이지 award API 호출 (`POST /api/ap/booking/avail/awardAvailability`)
   - 헤더 4종 필수: `ksessionId`, `timestamp`, `channel: pc`, `Content-Type`
   - 호출 간 2초 이상 간격

### 걸렸던 함정 메모

- **오류코드는 두 종류를 구분해야 한다.**
  - `ERT.10032` = `"The requested departure date is too late"` → **오픈 한계일 초과**(아직 안 열림)
  - `ERT.7190` = `"We are unable to find recommendations"` → **날짜는 열렸는데 줄 운임이 없음**
  둘을 묶어 "미오픈"으로 처리하면 틀린다. **한계일 판정은 `ERT.10032`로만 한다.**
- 오류 판정을 `/^IBE-/`로만 하면 `ERT.` 계열이 통과해 **오픈 한계일 초과로 오판된다.** `j.code`가 있으면 전부 오류로 처리할 것.
- 브리지의 `browser_run_code_unsafe`에 넘기는 코드는 **`async (page) => { ... }` 형태의 표현식**이어야 한다.
  `return await ...`로 시작하거나 top-level `await`를 쓰면 SyntaxError.
- 인페이지 루프는 **10일 단위로 끊는다.** 2.2초 페이싱으로 30일치를 돌리면 응답이 잘린다.
- 프레스티지가 전부 매진으로 보이면 API 착시인지 먼저 의심할 것.
  → ICN-NRT 2027-02을 찍어 프레스티지 1~2석이 정상 표시되는 걸 확인했으므로 **이번 결과는 실제 매진**이다.
- 캘린더의 `emptyCode:"NAV"`는 `soldOut:false`인 채로 온다. **매진이 아니라 운임 미개설이다.**

## 9. 글감 메모

- **"매진이 매진이 아니었다"** — 6-3이 그대로 한 편이다. 오픈 당일 매진으로 보였던 파리 귀국편이 엿새 뒤 9석으로 돌아온 기록.
  *"직접 가봤더니"*류 스냅샷 정보의 한계를 데이터로 보여줄 수 있다. **이번 회차에서 제일 값나가는 소재.**
- **"파리는 갈 수는 있는데 돌아올 수가 없다"** — 가는 편만 보고 표를 잡으면 생기는 함정. 4-1 표 하나로 설명된다.
- **"361일이 아니라 360일"** — 통념과 다른 실측값. 세 시점 측정으로 확정됐다.
- **"프레스티지는 끝난 싸움"** — 양방향 12일치 전부 0석. 스카이팀·대기예약으로 넘어가는 다음 편 예고.
- **노선별 통념 검증**: 파리 성립(가는 편은 여유, 오는 편 전멸) / 뉴욕 반증(가장 무난) / 라스베이거스 압승 / 프라하 기각(편수 부족).
