## 1. 목표 — 완성도 기준

- **클립만 보고도 블로그 글 내용을 정확히 알 수 있어야 한다.** 움직이는 컷 몇 개를 만들어 주는 걸로 끝내지 않는다 (10/6 사용자 지적).
- 컷 고르기 → 영상화(움직임) → 이어 붙이기 → 자막 → 내레이션까지 **완성 mp4**로 넘긴다.
- 배경음악만 사용자가 클립 편집기에서 넣는다 (2-3). `[확인 필요]` 올리는 경로가 PC 클립 크리에이터로 고정(2-4)된 뒤에도 이 방식이 되는지는 2-3 참고

## 2. 블로그와 연결

### 2-1. 연결 방법 (10/6 결정 — PC 클립 크리에이터 고정)
- **클립 → 글**: PC 업로드 화면 **상세 정보 → 콘텐츠 링크 → 블로그** 에서 후기 글을 고른다(2-4, `fill_clip.py`가 채움)
- **글 → 클립**: 크리에이터로 올린 클립은 블로그 앱 [클립] 탭에 안 뜬다 → 후기 글에 클립 링크 한 줄(`_1.컨텐츠\_자동화\add_link.py`)
- 🚫 블로그 앱 [+] → [클립 만들기] → [블로그] 스티커 방식은 쓰지 않는다(10/6 첫 테스트 때 방식. 「블로그 연동 클립」이라 크리에이터 쪽 분석·수익과 다른 칸이다)
- 보조: 블로그 앱 홈편집 → 외부채널 링크(커스텀 링크 1개)

### 2-2. 어떤 글을 클립으로 만드나
기준 네 가지: ① 직접 찍은 사진·영상이 있다 ② 숫자 하나로 첫 2초를 잡을 수 있다 ③ 지금이 그 계절이다 ④ 세로 화면이 어울린다.
- 기한이 있는 글(축제 등)은 **종료 전 마지막 주말에 걸리게** 올린다 (감악산: 10/11 종료 → 10/8~9)
- 후보 예: 화담숲 단풍 예약, 대한항공 좌석 오픈 시간(화면 녹화), 후쿠오카 사파리, 수암봉 퇴근 산행, 민둥산 억새(다녀온 뒤)
- 재료는 직접 찍은 사진·영상과 **내 화면 녹화**뿐이다. 남의 사진·영상·화면은 쓰지 않는다(마스터 6-7)
- **🎯 10/10부터 「몰아 만들기」 → 「한 편씩 정성」(사용자 결정)**: 클립이 충분히 쌓였다(공개·예약 40여 편). 이제는 발행글 중 **클립으로 잘 될 글 하나를 골라** 5-1 예산(편당 20~40크레딧)·1분 30초까지 써서 제대로 만든다. 고를 때는 위 네 기준 + 클립 성적(조회수 높은 결: 10/6 감악산 후기 3,174 · 경주 426 · 니지모리 388) + 블로그 글 유입을 본다. 하루 여러 편을 찍어 내지 않는다
- **클립 등록도 하루 발행 편수에 넣는다** — 하루 3편 기본, 필요하면 추가하되 최대 5편 (마스터 15장, 2026.10.7 사용자 결정)

### 2-3. 배경음악
- Higgsfield 음악 모델(sonilo_music 등)은 게임 제작 전용이라 쓰지 않는다
- **네이버 클립 편집기 음악 목록**에서 고른다(저작권 안전). 내레이션보다 작게
- 사용자가 음원 파일을 주면 그걸 넣는다
- 남의 영상·음원에서 소리를 따오지 않는다(마스터 6-7). 효과음은 make_clip 이 직접 합성한다(4-2-1)
- `[확인 필요]` 「클립 편집기」는 블로그 앱 [클립 만들기] 편집 화면이다. PC 클립 크리에이터 업로드(2-4)에도 음악 넣는 칸이 있는지는 이 문서로 확인되지 않는다

### 2-4. PC 자동 입력 — `fill_clip.py` (10/6)
- **올리는 경로는 PC 클립 크리에이터로 고정 (10/6 사용자 결정).** 블로그 앱 [+]→[클립 만들기]로 올린 「블로그 연동 클립」과는 서로 다른 칸이다. 크리에이터로 올린 클립은 클립 프로필·재생목록·분석·수익에 잡히고 **블로그 앱 [클립] 탭에는 안 뜬다** → 블로그 쪽은 후기 글에 클립 링크 한 줄(`_1.컨텐츠\_자동화\add_link.py`)로 보완
- **블로그 글이 발행된 뒤에 클립을 연결·등록한다**(마스터 2-4 — 아직 발행 안 한 글은 연결하지 않는다)
- 업로드는 **PC `clipcreators.naver.com` → [+ 업로드] → [동영상 업로드]**. 모바일 웹 clip.naver.com 은 「앱에서 이용」으로 막힌다
- PC에도 [블로그] 연결이 있다: **상세 정보 → 콘텐츠 링크 → 블로그** (글 목록에서 [선택]). 앱 스티커 대신 이걸 쓴다
- 스크립트: `_1.컨텐츠\_자동화\fill_clip.py <글폴더>\clip\clip_upload.json` (이미 영상을 넣은 화면이면 `--here`)
  - 블로그 자동화 프로필(`chrome_profile`)을 디버깅 포트 **9334**로 띄우고 붙는다 (9333 은 마일리지 조회용, 건드리지 않음)
  - 채우는 것: 영상 · 설명(300자) · 커버 후보 · 카테고리 2단 · **AI 활용 설정** · 광고 표시 · 정보태그(검색 → 선택) · 블로그 연결 · 댓글
  - 새 업로드는 **항상 새 탭**에서 연다(아직 등록 안 한 다른 클립 화면 보호)
  - **[등록]·[임시저장]은 누르지 않는다.** 사용자가 화면 확인 후 직접 누른다(공개 게시)
- `clip_upload.json` 항목: video, description, cover_index, category[2], ai, ad, info_tag{type,query,match}, blog(제목 일부), schedule, comments
- **AI 장면·움직임 컷의 빛은 장면마다 다르게**(마스터 5-5, 10/13): 노을·황금빛을 기본값으로 쓰지 않는다 — 맑은 낮·흐린 날·비·실내를 돌려 쓰고, 움직임 프롬프트에도 시간·날씨를 원본 그대로 두라고 적는다
- **AI 활용 설정**: Higgsfield 움직임 컷·AI 내레이션을 썼으면 반드시 켠다. 마스터 5-5의 캡션 표기 `(AI 생성 이미지)`를 영상에선 이 설정으로 대신한다(매체 예외)
- **광고 표시**: 제휴·협찬 글로 만든 클립은 광고 표시를 켠다(마스터 7장·16-9)
- 카테고리 예: 여행 > 국내여행 / 해외여행 / 항공 / 호텔 및 숙소. 축제는 정보태그 「공연·축제·전시」에서 축제명 검색(감악산 → 「감악산 꽃별 여행」)
- 미구현: **등록 예약 시각**(날짜 버튼 + 시·분 스크롤 선택기) — 예약 체크만 하고 시각은 손으로. 새 업로드의 파일 선택은 file chooser 가로채기로 넣는데 아직 실전 1회 전
- **블로그 연결 목록엔 최근 30편만** 뜬다. 오래된 글은 검색해야 하는데 **제목 단어로 검색하면 연결 제목에 `<em class="srch">` 가 글자로 박힌다**(네이버 버그) → `blog_query`에 본문에만 있는 단어(인왕산: 「서촌가락」)
- **블로그 검색에 안 잡히는 글도 있다**(10/7 용마산 9/28 글: 「용마산」「손두부」「용마봉」 다 0건 — 그 글을 링크한 다른 글만 나옴). 하루 지나면 잡힌다(10/7 확인 — 「용마산」은 em 박힘, 본문 단어 「동의초등학교」는 깨끗). 초안으로 두고 다음 날 [콘텐츠] → 초안 행 클릭으로 열어 연결
- CDP 연결이 「connected」 뒤에 멈추면 안 쓰는 탭(clip.naver.com 등)을 `/json/close/<id>`로 닫고 다시
- 영상은 CDP `DOM.setFileInputFiles`로 경로만 넘긴다 (Playwright 파일 전송은 50MB 제한 — 72초 클립이 75MB)
- 커버 후보는 영상 처리가 끝난 뒤에 생긴다 → 비어 있으면 첫 컷이 기본
- **원하는 장면을 커버로**: `clip_upload.json` 에 `"cover_at": 3.0`(초) → 그 장면을 뽑아 커버 칸에 직접 올린다(jpg·png 업로드 칸이 있다). 자동 후보 3~6개엔 숫자가 다 뜬 장면이 없을 때가 많다(10/7 마일리지 가치: 사용자가 「다섯 배 넘게 차이」까지 뜬 화면을 원함). 후킹 장면이 다 뜬 시각으로 잡는다
- **🖼️ 커버(첫 페이지)는 그래프·차트·숫자 카드가 아니라 임팩트 있는 후킹 이미지 (10/9 사용자 결정, 마스터 5-4 와 같은 원칙)**: 그래프는 엔지니어인 나에겐 재밌어도 보는 사람은 흥미를 안 느낀다 — 수요에 맞춘다. 마일리지·엔화처럼 숫자가 주인공인 클립도
- **(2026.10.15 마스터 5-4 동기화) 커버도 썸네일 세 질문** — ① 클립 전체가 무엇에 관한 것인지 말하며 궁금증 ② 커버만 봐도 블로그 글 제목이 떠오름 ③ 그 장면이 클립 안에 실제로 나온다. 커버 전용으로만 만든 장면(클립에 안 나오는 것)은 ③✕.
  - 숫자형(dataviz) 클립은 **첫 장면(s0)을 화면 꽉 찬 후킹 이미지 + 질문형 자막**으로 만들고 `cover_at` 을 그 장면에 둔다. 그래프·카드는 두 번째 장면부터
  - 이미지는 ① 내가 찍은 사진 중 가장 궁금한 장면 ② 없으면 Higgsfield AI 장면(마스터 5-5: 글자·숫자·로고·얼굴 금지, 화면에 「AI 생성 이미지」) — 블로그 썸네일로 만든 AI 장면(img1 류)을 그대로 쓰면 글과 클립이 같은 얼굴이 된다

### 3-0. 연결성 — 장면이 「응? 갑자기?」가 되지 않게 (10/11 사용자)
> 대영박물관 편: 「4만원 내는 로직은 이해가는데, 갑자기 '30분 전 도착해야 해'가 나오니 이건 무슨 게시물이야?」

- 콘티를 다 쓰면 장면 첫마디만 이어 읽어 본다 — 그것만으로 이야기가 이어지면 통과

### 4-1. SEGMENTS 표 한 줄 = 컷 하나
| 키 | 뜻 |

| `texts` | `('top'|'mid'|'small', '문장\n둘째 줄')`, `{ }` 안은 노란색 강조 |

| `mosaic=[(x0,y0,x1,y1)]` | **얼굴 가리기**(비율 좌표). 굵은 모자이크, 상자 가로를 6칸으로 나눈 블록. 순서는 3-2(크롭 → 컷 제외 → 모자이크) |

### 4-2. 화면 규칙
- 1080×1920, 30fps. 사진은 2배 크기로 만든 뒤 천천히 10% 확대(zoompan)
- 사진 확대는 **PIL 소수점 확대 + 시작·끝 천천히(smoothstep), 최대 1.08배**. ffmpeg zoompan 은 정수 픽셀로 끊겨 「툭툭·엉거주춤」해 보였다(10/7 사용자 지적)
- **자연 풍경(풀·잎·물·버들)은 Higgsfield 로 실제 흔들림**을 넣는다 — 프롬프트는 「Static camera … No camera movement」로 카메라를 묶는다(경주 은행나무·버들못·물길·억새, 두물머리 느티나무 모두 흔들림 없이 성공)
- 얼굴은 3-2 순서대로 — 크롭(`cx`) → 컷 제외 → **굵은 모자이크**(`mosaic=[(x0,y0,x1,y1)]`, 블록 6칸). 블러 금지. 모자이크는 머리에 딱 맞게 잡고 컷 처음·끝 프레임 둘 다 확인(확대로 위치가 움직인다)
  - **상자 좌표는 `python clipkit\face_boxes.py <사진 또는 폴더> --preview` 로 먼저 뽑는다(10/19)** — 사진마다 `mosaic=[(…)]` 한 줄과 `_faces.jpg` 미리보기(6칸 블록). 머리카락까지 25% 넓혀 준다. **검출은 후보일 뿐** — 옆얼굴·작은 얼굴·뒷모습은 못 찾으니 7장 체크는 그대로 눈으로
- 컷 사이 0.25초 크로스페이드
- **Higgsfield 영상(약 5.9초)보다 대사가 길면 마지막 장면을 붙잡아 늘린다**(tpad). 안 그러면 컷 파일이 짧아져 뒤 사진이 전부 대사보다 앞서 바뀐다(10/7 한정선 첫 대사 7.4초 → 2초씩 밀림, 사용자 지적)
- 자막이 **사진의 주인공(꽃·잎·음식)을 가리면 'top' 으로** 올린다(10/7 세미원 쟁반 잎). 검수 때 주인공 위치를 본다
- **자막은 이미지의 핵심 부분을 가리지 않게 넣는다(10/9 사용자 지시)** — 컷마다 「이 사진에서 보여 줘야 할 것」(돌리네·정상석·표지판 글자·그래프 곡선·가격표 숫자)이 화면의 어디에 있는지 먼저 보고, 자막을 그 반대쪽에 둔다
  - 핵심이 아래쪽이면 'top', 위쪽이면 'mid', 화면 전체를 채우면 자막을 짧게 한 줄로 줄이거나 focus 로 핵심을 자막 없는 쪽으로 민다
  - **`fit=True` 이미지(그래프·캡처·고도표)는 화면 위쪽(약 7%~60%)에 놓이므로 자막은 'mid'(아래)로.** 'top' 을 쓰면 그래프 위를 덮는다(10/9 민둥산 고도표)
  - 지형 사진은 「보여 줄 땅」의 위치를 따로 확인(10/9 민둥산 돌리네 — 'mid' 자막이 움푹 꺼진 곳을 덮음 → 'top' + focus 아래로)
  - dataviz 막대·범위 점의 이름 칸은 270px(x 90~360)뿐. 이름이 길면 막대 선에 글자가 깔린다 → 이름은 `label` 로 줄 위에 따로 두고 막대 이름은 ''(10/9 마일리지 카드 「삿포로 왕복(24.1, 영수증)」)
  - 검수 시트(4-3)를 볼 때 자막 상자와 핵심 부분이 겹치는지를 컷마다 체크 항목으로 본다
- 세로로 긴 **휴대폰 캡처는 fit 말고 화면을 채운다**(fit 이면 글씨가 안 읽힘). 캡처 속 핵심 줄을 자막이 가리면 자막을 'top' 으로
- 검수는 컷 중간 한 장씩이 아니라 **대사 시작 시각마다** 프레임을 뽑아 사진·자막·대사가 맞는지 본다
- 자막: 맑은 고딕 Bold, 흰 글자 + 검은 테두리 + 반투명 둥근 상자, **숫자·핵심어는 노란색** (마스터 4-1 볼드 섹션당 1~2개와 다른 매체 예외)
- 위치: 본 자막은 세로 1300px 가운데(클립 하단 버튼에 안 가림), 후킹은 위쪽 300px
- 한 줄이 화면 폭(W-140)을 넘으면 **글자 크기가 자동으로 줄어든다**(10/7). 그래도 길면 두 줄로 나눈다
- 날짜 라벨의 **요일은 달력으로 확인해서** 넣는다 (용마산 9/27 을 토요일로 잘못 넣었다)
- 한 줄이 화면 밖으로 나가면 두 줄로 나눈다 (「먹거리장터에서\n…」)
- fit 사진은 화면 위 56% 안에 넣어 자막이 사진 글씨를 덮지 않게 한다

### 4-2-1. v2 기능 (10/7 밴티지에서 처음, `_1.컨텐츠\정보(move)_컨텐츠\260929_등산화3편\clip\make_clip.py`)

## 5. Higgsfield — 움직임 컷

- **실제 사진에 움직임만** 넣는다. 사람·꽃·건물을 새로 만들지 않는다(진정성). 한 클립에 ~~1~2컷~~ → **3~5컷(10/10, 5-1)**
- 마스터 5-6 의 AI 삽화(블로그 글용 `gpt_image_2_5` 그림)는 **클립 컷으로 쓰지 않는다.** 마스터 5-5 금지(로고·얼굴·읽히는 글자 재현, 남의 사진을 참고 이미지로)는 움직임 컷에도 그대로
- 잘 맞는 장면: 넓은 풍경(앞으로 밀기 + 구름), 풍력발전기·물·깃발처럼 원래 움직이는 것
- 모델: `minimax_hailuo` / variant `minimax-2.3-fast` / 6초 / 768 = **4크레딧**. (kling3_0 std 무음 7.5, grok 22.5, seedance 28)
- 입력은 미리 9:16(1080×1920)으로 잘라 올린다
- 업로드: `media_upload` → curl PUT 에 **`-H "If-None-Match: *"` 필수** → `media_confirm`
- 무관한 프리셋(「IN THE DARK」 등)을 권하면 `declined_preset_id`로 거절하고 그대로 생성
- **주인공이 작은 사진(바닥의 신발 등)은 Higgsfield 금지** — 카메라가 엉뚱한 쪽으로 밀고 들어가 주인공이 사라지고 배경이 바뀐다(10/7 밴티지). 넓은 풍경·물·풀만
- 「static camera」라고 써도 살짝 움직인다 → 프레임을 뽑아 확인, 이상하면 앞부분만 쓴다
- 생성 전 `get_cost`. 크레딧 10/6 기준 plus 1,199
- **크레딧 없이 되는 대안(10/19, 시험 전)**: 넓은 풍경·건물에 「카메라가 천천히 들어가는」 움직임만 필요하면 `python clipkit\depth_motion.py <사진> --preset zoomin --amp 0.4` (DepthFlow 깊이 패럴랙스, 결과 `_depth.mp4` 를 `src='video:…'` 로). 물·풀·깃발의 실제 흔들림은 못 만드니 그건 Higgsfield. 주인공 작은 사진·사람 사진 금지는 같다. 데스크톱 첫 실행 때 한 장으로 시간을 재고(GPU 없으면 느림) Higgsfield 컷과 나란히 비교해 쓸지 정한다

### 5-1. 품질 올리기 — 크레딧은 아끼지 말고 쓴다 (10/10 사용자 결정)

### 6-1-2. 귀로만 듣는 문장 — 짧은 말 + 연결 어미는 풀어 쓴다 (10/11 사용자, 중요)
> 「유튜브에서 '사고 재고' 한 영상은~ 이라고 붙이니 이게 뭔 말이야 느낌. 아싸리 '제품을 사서 직접 재고 평가한'처럼 구체적인 글귀를 붙이지 않으면 맥락이나 말투가 다른 의미를 띤다.」
- 내레이션은 **글이 아니라 소리**다. 글에선 앞뒤 문장이 보여 뜻이 잡히지만, 귀로는 한 번 지나가면 끝이다
- **짧은 동사 + 연결 어미(-고·-서·-며·-면)** 는 다른 낱말로 들린다: 「사고」(사고 = accident) · 「재고」(재고 = 창고에 쌓인 물건) · 「가고」 · 「쓰고」. 연달아 붙이면(「사서 재고 밟아 본」) 더 헷갈린다
- 그럴 땐 **무엇을 · 어떻게** 를 붙여 문장을 늘린다: 「직접 사서 재고 밟아 본 건」 → 「제품을 직접 사서, 저울에 달아 보고 밟아 보며 비교한 영상은」 / 「직접 재고 직접 가 보는 데」 → 「직접 가 보고 직접 재 보는 데」
- 글 전체 맥락에서 그 말이 무슨 뜻인지 **처음 듣는 사람 기준**으로 다시 읽는다. 블로그 용어(검색 유입·홈판·사이트 유입)도 같다 → 「검색창에 쳐서 들어온 사람」「네이버 앱 첫 화면 추천 글(홈판)」처럼 풀어 쓴다(10/11 블로그 조회수 편 「영상만 보면 뭔 소리야」)
- **의미 덩어리 하나 = 한 문장(또는 쉼표 구간) = 자막 한 줄 15자 안** (10/11 사용자: 「복귀편을 열린 / 날 밤에 열어 봤어」처럼 호흡이 끊기면 한국인 귀에 이상하다 → 문장을 끊을 때도 의미 단락으로)
  - 대본을 쓸 때 **쉼표·마침표를 의미가 갈리는 곳에만** 찍고, 그 사이를 15자 안으로 쓴다. 넘으면 문장을 둘로 나눈다: 「2027년 10월 연휴 복귀편을 열린 날 밤에 열어 봤어」 → 「2027년 10월 연휴 복귀편. 좌석이 열린 날 밤에 하나씩 열어 봤어.」
  - 꾸미는 말과 꾸밈 받는 말(「열린 / 날 밤」「복귀편을 / 열린」) 사이에는 쉼표도 줄바꿈도 두지 않는다
  - 자막은 의미 덩어리 하나씩 띄운다(`shorts.py` `_chunks`). 15자를 넘는 덩어리만 두 줄로 — 가운데 가까이, **조사·어미 뒤**(은·는·이·가·을·를·에·서·고·면…)에서 끊고, 앞말에 붙는 말(「설명해 / 줄」「기억나는 / 건」「3만 / 원대」「입장료가 / 아니라」)과 맨몸 명사 뒤(「방식 / 문제」)는 가르지 않으며, 한 줄에 「들어.」처럼 낱말 하나만 남기지 않는다. 글자 수로 기계적으로 넘기지 않는다
  - 검산(`qa_clip.py` ③-2)이 30자 넘는 덩어리는 고칠 것으로, 16~30자는 나눌 수 있으면 나누라고 표시한다
- **뜻이 둘 이상이거나 기준이 안 보이는 말은 쓰지 않는다** (10/11 사용자: 「찾는 사람이 거의 없다는 게 검색 유입 기준이지? 애매해」「재 보는 데 → 직접 체험한다는 뜻? 모호해」)
  - 기준이 숨은 말 → 기준과 숫자로: 「찾는 사람이 거의 없는 글」→「한 달 검색량은 110뿐이었는데」
  - 뜻이 갈리는 동사 → 무엇을·어떻게: 「재 보는 데」→「현장에 가 보고, 실제로 측정하는 데」
  - 비유 → 사실로: 「하늘이 열렸고」→「비가 그쳤고」 · 「읽어 줄 사람」→「작품 이야기를 들려줄 사람」
  - 가리키는 게 안 보이는 말 → 대상으로: 「같은 날」→「4일」 · 「숫자는」→「남은 좌석은」 · 복귀편 이야기 중 「출발편」→「가는 편」 · 「오후 편 두 편」(같은 편 이틀치)→「3일과 4일, 같은 오후 편」
  - 발행글 표현을 그대로 옮겨도 귀로는 모호할 수 있다(발행글 「직접 재고 직접 가 보는」) — 영상은 처음 듣는 사람 기준으로 다시 쓴다
  - 녹음 전 `pron_book.py check` 가 자주 걸리는 모호한 말(PATTERNS)을 경고한다
- **같은 말을 두 번 쓰지 않는다** (10/11 사용자: 「~위에 ~위에 두 번 나와서 듣기 이상」「영어처럼 한글도 같은 단어 두 번을 꺼린다」)
  - 한 줄(장면) 안, 그리고 **다음 줄 첫머리까지**: 같은 낱말 줄기(「위에·위로」「직접 … 직접」「줄이 … 줄을」), 같은 보조 동사(「달아 보고, 밟아 보며」「본 … 열어 봤어」)
  - 고치는 법: 하나를 빼거나(「직접 가 보고 직접 재 보는」→「직접 가서 재 보는」), 다른 말로(「본 출발편」→「확인한 출발편」, 「바뀌어 있었어 / 바뀌어」→「달라져」)
  - 일부러 맞춘 대구는 괜찮다: 「반팔 챙겨? 아니면 외투 챙겨?」「싼 스틱이든 비싼 스틱이든」
  - **지적받은 줄만 고치지 않는다** — 같은 종류의 문제를 그 편 전체와 같이 만든 다른 편까지 다시 훑는다(10/11 「앞서 말했는데 왜 안 고쳐지나」)
  - 검산 `qa_clip.py` ③-3(`clipkit\repeat_check.py`)이 「고칠 것」이면 통과하지 않는다
- **화면 글에 특수 기호(✕ ✓ ★ 등) 쓰지 않는다** — 글꼴에 없는 기호는 네모(□)로 나온다(10/11 고깃집 「1층 ✕」). 「아니고」「O·X」처럼 글자로. ○ · → 는 나온다
- **글이 박힌 카드·표 이미지는 `whole=True`** (10/11 사용자: 복귀편 종합 카드 「위에 제목 다 짤려」) — `shorts` 장면은 확대 여유로 가운데 80%만 보여서 가장자리 글이 잘린다. 검산은 화면에 그리는 글자만 보므로, 이미지 안 글자는 **stills·프레임으로 눈으로** 본다
- **장면 말이 끝나면 약 1초 쉬고 다음 장면으로** (10/11 사용자: 말 끝나자마자 넘어가면 듣는 사람이 속도를 못 따라간다)
  - `shorts.py` `TAIL = 1.0` — 장면 길이 = 내레이션 + 앞 0.15초 + 뒤 1.0초. 쉼 동안 마지막 자막은 화면에 남긴다
  - 마지막 장면(댓글 질문)은 1초보다 길게 둬도 좋다
- **한 장면 안에서도 질문·문장이 바뀌는 곳은 0.5초 쉼** (10/11 사용자: 「반팔이야? 외투야? / 내가 간 나흘은」 사이가 빠르다)
  - 빌드가 녹음 속 0.3초 넘는 쉼을 잘라 내므로, 다시 녹음하지 말고 장면에 `breath=[(틈 번호, 0.55)]` — 틈 번호는 말 사이 틈을 0부터 센다(`tactics.narr_gaps`)
  - 자막 경계는 가까운 틈(0.6초 안)으로 맞춰져서, 쉼 뒤 자막이 먼저 뜨지 않는다
- 질문을 두 개로 나눌 땐 각각 물음표: 「반팔 챙겨, 겉옷 챙겨?」는 「반팔 챙겨」가 마침표처럼 내려앉는다 → 「반팔 챙겨? 아니면 겉옷 챙겨?」(10/11)

### 6-1-3. 피해야 할 발음 장부 — 걸린 건 쌓아서 다음 대본에서 먼저 피한다 (10/11 사용자 제안)
> 「반복적으로 검토할 때 걸리는 받침이나 단어가 있으면, 그걸 기반으로 피해야 할 발음의 데이터를 쌓을 수 있지 않아?」
- 장부: `_1.컨텐츠\_자동화\clipkit\pron_book.json` — 낱말 · 어떻게 잘못 들렸나 · 몇 번 · 바꾼 말 · 메모
- **쌓기 ①(자동)**: `narr_pick.py` 가 녹음마다 받아쓰기와 자막을 맞춰 보고, 어긋난 낱말(조사 뗀 꼴)을 더한다
- **쌓기 ②(사용자 귀)**: 사용자가 「발음이 이상해」라고 하면 그 자리에서 `python pron_book.py add <낱말> --heard 들린말 --fix 바꾼말 --note "메모"` — 사용자 지적은 따로 세어 더 무겁게 본다
- **쓰기**: 대본을 쓰고 **녹음 전에** `python pron_book.py check narration\<EP>\script.txt` → 걸리면 녹음 전에 말을 바꾼다. 검산 `qa_clip.py` ③-4 도 같은 걸 보여 준다(경고만 — 받아쓰기 ⑦과 귀로 확인)
- 낱말이 아니라 **꼴**로 걸리는 것도 장부 옆에 둔다(`PATTERNS`): 짧은 동사+-고(사고·재고) · 숫자 끝 「이」+조사(「오십이라고」→50이라고) · 「하얬어」류 과거형
- 지금까지 쌓인 것(10/11): 겉옷→거두·거도(→외투) · 하얬어(못 읽음) · 시월→7월(MiniMax) · 손잡이→스푼잡이 · 오십이라고→50이라고 · 사고 재고 · 영대이/공대이 박자 · 14만원대 · 대영→대형
- **장부에 이미 걸린 말은 「받아쓰기로 확인」하며 그대로 녹음하지 않는다 — 녹음 전에 바꾼다.** (10/11 「오십이라고」를 경고 보고도 녹음 → 또 50으로 받아써짐) 숫자가 계속 걸리면 소리에서 빼고 화면 큰 글씨로만 보여 준다(「52 눈금 위 STOP」)
- **고유명사가 일반 낱말로 들려 앞 수식어에 붙으면 뜻이 바뀐다** (10/11 하코다테 「도야호가 내려다보이는 사이로 전망대」 → 「보이는 사이로(틈으로)」로 들림 — 사용자 지적): 수식어 **뒤에서** 쉼표로 끊고(「내려다보이는,」), 이름은 **대본에서만 붙여 써** 한 덩어리로 읽힌다(「사이로전망대에서」). 화면 자막은 공식 표기(「사이로 전망대」) 그대로
- **같은 voice_id 로 뽑아도 가끔 다른(여자) 목소리가 나온다** (10/11 하코다테 n04 두 개 중 하나 — 사용자 「갑자기 여자 목소리」, 받아쓰기는 멀쩡해서 못 잡았다): `clipkit\voice_check.py` 가 음색 거리(중앙 음색과 6.0 넘음)로 가른다. narr_pick 은 고르기 전에 빼고, qa_clip ⑤ 는 완성 줄에서 걸리면 ❌. 높이(Hz)만으론 못 가른다(Kevin 127~171Hz · 여자 184Hz)
- `python pron_book.py list` 로 많이 걸린 순서대로 본다. 같은 낱말이 3번 넘게 걸리면 이 절에 「쓰지 않는 말」로 올린다

### 6-2. 대사 쓰는 법
- 자막을 그대로 읽히지 말고 **말로 다듬는다**. 컷 하나에 한 문장
- 대사에도 **마스터 3장(공학·직업 비유 금지)** 과 **3-1(같은 비유 돌려쓰기 금지·쉬는 말 문·칸·계단·뚜껑, 대체어도 비유 장부로 센다)** 을 그대로 적용한다. 반말(마스터 2-7)
- **내레이션은 만들 때마다 받아쓰기 검사**: `python _1.컨텐츠\_자동화\check_narration.py <글폴더>\clip` (whisper medium). MiniMax 가 대본 끝에 **없는 말을 붙인다**(10/7 한정선 n08 「그리고 나즈게이트」, 세미원 n01 「이.」 — 사용자가 듣고 지적). 타임스탬프 보고 붙은 꼬리 앞에서 `-t` 로 잘라내고 원본은 `.bak`
- **문장 사이 빈틈**: MiniMax 가 1~1.7초씩 쉬어 뚝뚝 끊긴다(10/7 사용자 지적) → make_clip 이 0.4초 넘는 빈틈을 0.4초로 묶는다. 그래도 끊기면 두 문장을 「~이고」로 이어 한 문장으로 다시 생성
- **영어 외래어는 피한다**: 「앱 팁 하나」의 「팁」이 영어 발음으로 튐 → 「요령」. 꼭 필요한 말(앱, 웨이팅 등)만 남긴다
- 「구구 세트」처럼 숫자로 오해될 말은 풀어 쓴다(「아홉 개짜리 세트」)
- **사람 이름이 된소리로 뭉개지면 「○○○ 선수」를 붙인다**: 「엄지성이」가 「엄지썽」으로 났다 → 「엄지성 선수가」로 사용자가 귀로 확인(10/8). 쉼표로 끊기(「엄, 지, 성이」)보다 나았다. 한 줄에 이름이 둘이면 둘 다 「선수」로 맞춘다
- **호칭은 한 클립 안에서 통일 (10/8 사용자 결정)**: 선수는 국적 상관없이 **전부 「○○○ 선수」**(상대팀 요코야마 선수 포함), 감독은 **전부 「○○○ 감독」**(이민성 감독인데 김은중만 맨이름 → 어색). 일부만 붙이면 나머지가 낮춰 부르는 것처럼 들린다. 화면 자막·클립 설명도 같은 호칭으로. 팀 이름(김은중호)·선수 이름표(점 아래 이름)는 그대로
- **외국 지명이 이상하게 읽히면 소리 나는 대로 풀어 쓴다**: 「다롄」이 「다련」으로 났다 → 「다레엔」을 사용자가 귀로 골랐다(10/8, 「중국 다르엔」·「다, 롄」보다 나음). 이름·지명은 샘플 2~3개를 「삐」로 구분한 파일 하나로 들려주고 고르게 한다
- **「…」(말줄임)는 되도록 쓰지 않는다** — MiniMax 가 가끔 같은 소리를 수십 초 반복하는 깨진 파일을 준다(10/7 한정선). 쉼은 쉼표로. make_clip 이 12초 넘는 줄을 막는다
- 숫자는 소리 나는 대로 풀어 쓴다: 13:11 → 「한 시 십일 분」, 3,000원 → 「삼천 원」, 10/11 → 「시월 십일 일」
- **스코어는 붙여 쓴다**: 0-2 → 「영대이」(「공」 아님). 「영 대 이」로 띄우면 「영대~이」「삼~대이」로 박자가 끊긴다(10/9 사용자). 받아쓰기에서 「3대1」처럼 틀리게 들리면 2~3번 다시 뽑아 맞게 들리는 것을 쓴다
- **「14만 원대」 같은 어림 금액은 발음이 꼬이기 쉽다**(10/9 프라나 사용자 지적) → 소리에선 빼고 금액은 화면 자막으로
- 마지막 컷은 결론 + 「자세한 건 블로그에 적어 놨어」 → **10/7부터는 블로그 글 끝의 질문을 그대로 읽고 「댓글로 알려줘」**(3-3 ⑧)
- 파일은 `clip\narration\n00.mp3`~ (번호 = 컷 번호). 있으면 `make_clip.py`가 컷 길이를 「목소리 + 0.5초」 이상으로 늘리고 컷 시작 0.15초 뒤에 얹는다
- 비용: 문장당 0.15크레딧. **한 번에 3줄씩** 보낸다(12줄을 한꺼번에 보내면 rate limit·「크레딧 부족」 오류가 섞여 난다)

### 6-3. 새 결의 목소리 고르는 절차
1. 사용자가 원하는 느낌(참고 영상)을 받는다
2. 같은 후킹 문장으로 샘플 4개를 뽑아 들려준다 → 사용자가 고른다. **나는 소리를 못 들으니 고르는 건 사용자**
3. 엔진 순서: `minimax` → `elevenlabs` → `seed_speech`. `seed_audio`(기본 모델)는 「영어 느낌이 강하다」로 탈락(10/6). `cozy_voice`는 프리셋 목소리를 못 씀(400)
4. Higgsfield 목소리 목록(`list_voices`)은 영어권 이름이다. 한국어로 다 어색하면 → 타입캐스트·캡컷에서 사용자가 직접 뽑은 파일을 받거나, 본인 녹음을 `create_voice`로 등록

### 6-3-1. 연출은 대본으로 (10/6 확인)
- Higgsfield 경유 MiniMax 는 감정·속도·음높이 옵션이 막혀 있다. 넘길 수 있는 건 엔진·목소리·대본뿐
- 그래서 **대본 문장부호·말투로 연출**: 충격 「십칠만 오천 원?!」, 한숨 「하아,」, 들뜸 「야, 이거 봐봐!」, 뜸 「근데,」 — 쉼은 쉼표로(6-2 「…」 되도록 쓰지 않는다, 10/7)
  - 예외: 망설임 연출에 「…」가 꼭 필요하면 **클립당 1회**만. 만든 뒤 그 줄 길이와 받아쓰기 검사(6-2)로 깨진 파일인지 확인
- 줄마다 따로 생성하니 줄마다 연출을 다르게. 편집에서 특정 줄 속도·음높이, 반전 앞 정적 1초는 make_clip 단계에서 처리
- 가벼운 결 샘플 6개(Kevin·Benji·Cody·Archie·Dylan·Miles) 중 사용자가 Kevin 유지 → 「진중한 것 아니면 Kevin 통일」

### 6-4. 하지 않는 것
- **특정 유튜버·상용 TTS(캡컷·타입캐스트) 목소리를 녹음 파일로 복제하지 않는다.** 남의 목소리·상품이다. 정식으로 쓰려면 그 서비스에서 사용자가 직접 만든다
- 참고 영상의 목소리 정체를 귀로 판별하지 못한다 → 후보(캡컷 TTS / 타입캐스트 박창수·세진·지훈·하준 등)만 알려 주고 사용자가 들어 보게 한다
