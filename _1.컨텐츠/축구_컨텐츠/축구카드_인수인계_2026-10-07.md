## 0. 한 장 요약 (B 양식 이전 — 지난 글 다시 그릴 때)

```
[축구 카드 규격]
1. 폭 1080 고정, 높이 가변. 썸네일만 1080×1080 정사각.
2. 다크 배경. 상단 8px 색띠 → 제목(y74, Black 50) → 부제(y130, Regular 26)

3. 글마다 배경 톤을 바꾼다. 짝 글(프리뷰·후기)은 일부러 다른 색.
4. 의미색은 고정: 한국 주황 / 상대 청록 / 맞음 초록 / 반반 앰버 / 빗나감 빨강.
5. 전술판은 세로 미니 피치 두 장(430×700) 나란히. 부제에 「개념도」.

8. 렌더 후 한 장씩 열어 겹침·잘림을 본다. 안 보고 넘기지 않는다.
9. 기본 세트: 썸네일 → 네임카드 → 기록·채점 → 전술 도해. 설명 부족한 도해는 제작자 컨펌 후 발행.
```

### 4-4. 색 검사

데이터 표시(막대·선수 원·범례)에 쓰는 색 2개 이상은 검사기를 돌린다.

```
node scripts/validate_palette.js "#색1,#색2,#색3" --mode dark --surface "#배경"
```
(dataviz 스킬 폴더 안의 스크립트)

| 검사 | 기준 |
|---|---|
| Lightness band | 다크 모드 OKLCH L **0.48~0.67** — 너무 밝은 노랑이 자주 걸린다 |
| CVD separation | 색각이상 구분 ΔE — 한국 주황 ↔ 상대 청록은 통과 조합 |
| Contrast vs surface | 배경 대비 3:1 이상 |

- 걸리면 명도를 내리거나 채도를 올린다. 예: 광주 금색 #EEC448 → 표시용 #AC8620 (글자·띠용 밝은 금색은 따로 유지).
- 색이 비슷한 두 팀은 **라벨을 글자로 같이 붙인다**(색 하나에만 의미를 걸지 않는다).

## 5. 🗂️ 카드 종류

| 종류 | 언제 | 핵심 구성 |
|---|---|---|
| **썸네일** | 모든 글 첫 장 | 큰 제목 + 큰 숫자(스코어·0-2→3-2) + 칸 3개 + 결론 바. 정사각 |
| **네임카드(인물)** | 감독·선수 소개 | 상단 kicker → 이름(Black 104) → 소속 한 줄 → 라벨·값 6~8줄 → 결론 바(그 사람 한마디 요지) |
| **기록 비교** | 경기 결과 | 가운데 축 기준 좌우 막대(한국 주황 / 상대 청록), 양끝에 숫자 |
| **채점표** | 검증(후기) 글 | 프리뷰 관전 포인트 한 줄씩 + 오른쪽 판정 칩(맞음/반반/빗나감/보류) + 근거 한 줄 |
| **타임라인** | 시즌·경력 | 왼쪽 연도 + 세로선 + 원, 오른쪽 패널(굵은 사건 + 설명) |
| **득점·흐름** | 역전·교체 | 시간 / 득점자 / 합계를 한 줄씩. 마지막 줄만 PANEL2 + 금색 |
| **교체·연결 흐름** | 후반 변화 | 나간 선수 → 들어온 선수 + 역할 칩 / 득점 연결 박스 4칸 |
| **시나리오 반반** | 프리뷰 | 두 갈래를 좌우 패널로. 갈래별 색은 의미색과 겹치지 않게 |
| **전술판(개념도)** | 전술 설명 | 6장 참고 |

네임카드 줄 고르는 법:
- 첫 줄 = **지금 이 글과 관련된 핵심**(현재 소속·이번 대회 기록) — PANEL2 + ACCENT 라벨
- 나머지 = 확인된 이력만. 생년월일·선수 경력이 기사로 안 잡히면 **빼고 지도자 경력으로 채운다** (0-2)
- 결론 바 = 본인 발언의 **요지**(따옴표 직접 인용은 짧게, 출처 줄에 「인터뷰 요지」 표기)

## 6. ⚽ 전술판 규격

### 6-1. 피치

| 항목 | 값 |
|---|---|
| 배치 | 세로 미니 피치 **두 장 나란히** — A(75,230), B(575,230), 각 430×700 |
| 한 장만 | 가운데 정렬로 크게 (폭 600 안팎) |
| 색 | `PITCH` 배경 톤보다 살짝 초록·청 기운 (30,52,58) / 선 `LINE` (92,120,128), 두께 2 |
| 그리는 선 | 외곽·하프라인·센터서클·양쪽 페널티박스 |
| 피치 제목 | 피치 위 y=200, Black 26 — **왼쪽 = 좋아진 것(초록), 오른쪽 = 대가(빨강)** 처럼 대비로 |
| 공격 방향 | 피치마다 다를 수 있다 → 제목이나 태그로 「위로 공격」 표시 |

좌표는 `pt(PA, fx, fy)` — 피치 비율(0~1)로 찍는다. 픽셀로 직접 찍지 않는다.

### 6-2. 선수와 표시

| 요소 | 규격 |
|---|---|
| 선수 원 | 이름 있는 선수 r=16, 배경 선수 r=12~14. **크림 테두리 3px** |
| 이름 라벨 | `tag()` — 어두운 바탕(12,16,24) 둥근 상자 + Bold 17. 원 아래 r+17 (위가 비면 위) |
| 설명 태그 | 같은 `tag()`. 위험·대가는 글자색 RED |
| 화살표 | **점선 = 사람의 움직임, 실선 = 공(패스)**. 두께 4, 화살촉 14 |
| 구역 | `zone()` 반투명 둥근 사각형 alpha 45~60 — 초록 = 닫힌 곳, 빨강 = 빈 곳 |
| 범례 | 피치 아래 (y≈975) 가운데 — 원 + 팀 이름 |
| 번호 설명 | 범례 아래 최대 3줄, ACCENT 원 안 번호 + Bold 24 |
| 결론 바 | 맨 아래 — 「가운데를 닫은 대가는 오른쪽이었다」 같은 한 문장 |

### 6-3. 🚫 전술판에서 하지 않는 것

- 🚫 **부제에 「개념도」를 빼지 않는다.** 실제 위치를 잰 그림이 아니다.
- 🚫 **예상 선발 11명을 전부 이름 붙여 그리지 않는다** (축구 운영지침 4장 — 예상 선발 본문 금지). 이름은 설명에 필요한 1~3명만.
- 🚫 **실점 장면에서 실수한 선수 이름을 라벨로 달지 않는다.** 「오른쪽 풀백」처럼 자리로만 (실명 지목 금지, 상대·미성년 선수 포함).
- 🚫 동명이인·표기 불확실 선수는 이름 대신 자리 (「195cm 센터백」).
- 🚫 포메이션 숫자가 자료마다 갈리면 숫자를 쓰지 않고 모양만 그린다.
- 🚫 분석 채널 수치를 넣을 때 출처 없이 쓰지 않는다 → 출처 줄에 「○○ 해설 분석」·「채널 집계」.

## 7. 📌 내용 규칙 (카드에도 본문 규칙이 그대로 적용된다)

| 규칙 | 내용 |
|---|---|
| 저작물 | 🚫 구단·대회·방송사 **로고**, 선수 사진, 중계 화면, 영상 프레임, 유니폼 디자인 재현. 텍스트와 도형만 (마스터 6-7) |
| 숫자 | 기사·공식 기록으로 확인된 것만. 영상 속 숫자는 「채널 집계」로 표기. 갈리면 뭉갠다(「전반 10분이 되기도 전」) |
| 계산 | 직접 더하거나 나눈 숫자 금지 (0-4) |
| 이름 | 언론 명단·기록 화면으로 확인한 표기 (설영우·김명준·김준홍 등 축구 운영지침 4-1 이름 표기표) |
| 대회 이름 | 한 글 안에서 하나로 통일 (「ACL 엘리트」 ↔ ACLE 섞지 않기, 16-4) |
| 출처 줄 | 「기록: 뉴시스 · 다음 스포츠 (확인 날짜) · 직접 만든 이미지」 꼴 |
| 썸네일 | 큰 숫자·이름 중심. **(2026.10.11) 배경에 팀·감독 트레이드마크 AI 장면을 깔 수 있다**(축구 운영지침 6-2 — 글자·로고·얼굴 없음, 국기로 오해되는 색 배열 금지, 출처 줄에 「배경은 AI 생성 이미지」). 🚫 전광판 숫자가 박힌 AI 이미지, 남의 사진·엠블럼 |
| 전술 도해 | 가능하면 한 글에 1~2장. **근거가 장면을 다 설명하지 못하면 만든 뒤 제작자 컨펌 → 확인 전 발행본에 넣지 않음**(운영지침 6-2 ⑤) |
| AI 이미지 | 스포츠 글은 마스터 5-5 그대로 — 얼굴·로고·읽히는 글자 금지, 캡션 `(AI 생성 이미지, 실제 경기 장면 아님)` |

## 8. 🔍 검수 — 렌더 후 한 장씩 연다

**모든 카드를 이미지로 열어 본다.** 실제로 반복해서 난 문제:

| 문제 | 고치는 법 |
|---|---|
| 라벨이 다른 선수 원·화살표 끝에 겹침 | 라벨을 위로(`below=False`) 돌리거나 좌표를 0.03~0.05 옮김 |
| 화살표 끝이 라벨 상자를 찌름 | 화살표 끝점을 원 가장자리 앞에서 멈춤 |
| 긴 값이 패널 밖으로 넘침 | 글자 크기 2~4 낮추거나 `wrap()` 으로 줄바꿈, 패널 높이 재계산 |
| 마지막 패널 아래 빈 공간이 큼 | H 계산식 다시 (`top + 줄수×(높이+간격) + 30 + 82 + 80`) |
| 범례·번호 설명이 피치와 붙음 | 피치 하단(230+700=930) 아래 45px 이상 띄움 |
| 같은 색이 두 의미로 쓰임 | 4-2 표로 돌아가 한쪽 색 교체 |
| 밝은 노랑이 색 검사 탈락 | 표시용 색만 명도 내리고, 글자·띠는 밝은 색 유지 |

검수가 끝나면 작업 메모 「이미지」 절에 **톤(BG+ACCENT), 다른 글과 겹치지 않는지, 업로드 순서**를 적는다.

## 9. 🔁 작업 순서

1. 본문 초안·소제목 결론이 먼저 확정된다 (카드 결론 바 = 소제목 결론).
2. 4-3 표를 보고 **이번 글 톤**을 고른다. 짝 글이면 반대 계열로.
3. `football_cards_base.py` 를 불러와 `set_palette(BG=…, PANEL=…, PANEL2=…, MUTED=…, ACCENT=…)`.
4. 썸네일 → 네임카드 → 기록·채점 → 전술판 순으로 `cards.py` 작성.
5. 색 검사기(4-4).
6. 렌더 → **한 장씩 열어 검수**(8장) → 고쳐서 다시 렌더.
7. 본문에 `[[IMG:파일명 | 캡션]]` + 이미지 앞에 「왜 넣었는지」 한 줄 (마스터 16-4).
8. `images/` + `cards.py` + 초안을 압축해 전달. 4-3 표에 이번 톤 한 줄 추가.
